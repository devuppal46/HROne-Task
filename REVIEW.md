# REVIEW.md

Defects found in the starter `app/main.py`. Line numbers refer to the original starter. All are fixed in the new `app/main.py`; most have a test in `tests/test_rules_and_crud.py`.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | module, L22 | `MongoClient` is not `tz_aware`, so PyMongo returns naive datetimes. Anything that later calls `.timestamp()` or compares them with aware values is off by the server's UTC offset, or raises `TypeError`. | Run on a machine in IST: a stored 04:35Z punch reads back as 04:35 *local*, which is 5h30m wrong when converted to an instant. | `MongoClient(..., tz_aware=True, tzinfo=utc)`, plus `as_utc()` at every boundary. |
| 2 | module | No indexes are created. There is no unique constraint, and every list or analytics query scans the whole collection. | `/admin/explain` shows `COLLSCAN`; two concurrent creates of the same `emp_code` both succeed. | Startup `lifespan` creates the indexes idempotently (see DECISIONS.md). |
| 3 | `health()` L72 | Always returns 200 and never pings MongoDB. | Stop Mongo: `/health` still says `ok`. | `client.admin.command("ping")`; on `PyMongoError` it returns 503. `serverSelectionTimeoutMS=3000` so it does not hang. |
| 4 | `create_employee()` L79-83 | Check-then-insert. Two concurrent creates both pass `find_one`, then both insert. | 20 parallel `POST /employees` with the same code give several 201s. | Unique index on `emp_code`; `insert_one` catches `DuplicateKeyError` and returns 409. |
| 5 | `create_employee()` L82 | `datetime.now()` is naive local time, so it is stored as if it were UTC. | On an IST server, `created_at` is 5h30m in the future. | `datetime.now(timezone.utc)`. |
| 6 | `create_employee()` L85 | Returns `created_at` as a datetime (ISO string in JSON), not epoch ms. | Response has `"created_at": "2026-..."` instead of an integer. | `ser_employee()` converts every instant with `dt_to_ms()`. |

## Examined and judged not a defect

- **`load_dotenv()` (L20).** Its default is `override=False`, so real environment variables already win over `.env`. I kept it and made `override=False` explicit.
- **`int()` truncation in `compute_late_minutes` / `compute_overtime`.** For non-negative values `int()` equals floor, and negative values were clamped to 0. The bugs there are the reference instant (#18, #22) and the grace comparison (#19), not the truncation. I still use `//` on integer seconds for clarity.
- **The `IST = timezone(timedelta(hours=5, minutes=30))` constant.** It is correct; it just was not used where it mattered.
- **`(page - 1) * page_size` in `list_attendance`.** That slice was right. Only the employee list had the off-by-one.
- **`punch_out: None` / `work_hours: None` / `history: []` defaults at punch-in.** These match DATA_MODEL and are kept.
